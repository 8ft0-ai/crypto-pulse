# GitHub Pages generator changes

Use this skill for changes affecting the CryptoPulse Pages site, report rendering, RSS, manifest, archive pages, search indexes, or public presentation of generated reports.

## Source of truth

Raw Markdown reports are the source of truth. Generated `_site/` output is disposable and must not be edited or committed.

The site generator is:

```text
scripts/build_pages_site.py
```

Static styling is:

```text
site/assets/cryptopulse.css
```

## Generator-first rule

New report UI, changed report structure, archive navigation, RSS output, manifest metadata, or search/index behaviour usually requires generator changes. CSS may be necessary, but CSS alone is not a complete implementation when the required markup or data is missing.

A UX issue that asks for visible generated output must update the generator or renderer responsible for that output. Do not open a CSS-only PR for generator-required work.

## `_site/` boundary

Do not edit or commit `_site/`. Build output should be regenerated by GitHub Actions or local verification only.

If `_site/` appears in the diff, remove it before opening the PR.

## Demo and disclaimer language

Preserve or strengthen language that says CryptoPulse is AI-generated demo content and not financial advice, investment research, a recommendation, or a trading signal.

This applies to generated pages, feed descriptions, manifest metadata, report pages, archive pages, and footer text.

## Manifest, RSS, and search index changes

Update manifest, feed, and index generation only when the issue requires a metadata or discoverability change. Keep those changes narrow and avoid broad rewrites of unrelated generator code.

## CSS relationship

Update CSS only as a complement to generated markup. Add component-specific styles near related sections and avoid broad stylesheet churn.

## Verification

For generator-affecting work, run or reason through:

```bash
python scripts/build_pages_site.py
```

In the PR body, include verification notes covering:

- whether the generator was run;
- whether `_site/` was intentionally left uncommitted;
- any environment limitation that prevented a local build;
- the expected generated surfaces affected by the change.
