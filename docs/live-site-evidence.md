# Live-site evidence

CryptoPulse verifies the public GitHub Pages deployment after a successful `Publish CryptoPulse Pages` run.

The workflow is defined in:

```text
.github/workflows/verify-live-pages.yml
```

It can also be started manually from **Actions → Verify CryptoPulse Live Pages → Run workflow**.

## What it checks

The workflow opens the public homepage, latest report, archive and search pages with Chromium. It records HTTP status, page title, primary heading, skip-link presence, accessible link/button names, navigation status and serious or critical Axe violations.

CryptoPulse-specific regression checks also verify that:

- recent archive cards show time and timezone;
- `Data not specified` is absent;
- BTC/ETH metric groups are not duplicated within a card;
- disclaimer boilerplate is not promoted into the primary latest headline;
- the invalid legacy value `ETH, L2s, DeFi majors` is not rendered as an ETH metric.

A failed required assertion fails the workflow.

## Evidence artifact

Every run uploads an artifact named:

```text
cryptopulse-live-site-evidence
```

The artifact is retained for 30 days and contains:

```text
result.json
accessibility.json
homepage.html
homepage.txt
homepage.png
latest-report.html
latest-report.txt
latest-report.png
archive.html
archive.txt
archive.png
search.html
search.txt
search.png
```

`result.json` is the primary machine-readable summary. The HTML, visible text and screenshots provide review evidence for the exact public deployment.

## Inspecting evidence

1. Open the workflow run in GitHub Actions.
2. Confirm the `verify` job result.
3. Download `cryptopulse-live-site-evidence` from the run's **Artifacts** section.
4. Review `result.json` first, then use the page text or screenshots for visual confirmation.

The evidence is generated by Actions and is not committed. `_site/` remains disposable build output.
